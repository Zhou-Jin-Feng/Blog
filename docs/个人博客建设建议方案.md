> 文档版本：v1.0（可执行版）

## 1. 文档用途与执行规则

本文是首版博客从准备、开发、测试到上线的执行手册。执行者应按照 Stage 0 至 Stage 5 的顺序推进，不得把推荐方案当成已经确认的需求，也不得在当前阶段未通过时提前进入下一阶段。

### 1.1 状态定义

| 状态 | 含义 |
| --- | --- |
| 待开始 | 前置条件未满足或尚未执行 |
| 进行中 | 正在执行，尚未完成验收 |
| PASS | 任务完成且证据满足验收标准 |
| PASS WITH NOTES | 可以继续，但必须记录已接受的残余风险 |
| BLOCKED | 存在阻塞，必须先解决或由用户变更范围 |
| 不适用 | 经记录确认后，本阶段无需执行 |

### 1.2 强制执行规则

1. 一次只执行一个 Stage。
2. 每个 Stage 完成后记录命令结果、页面地址、截图或检查结果。
3. 只有闸门结果为 PASS 或经用户书面接受的 PASS WITH NOTES，才能进入下一 Stage。
4. 凭据、令牌、密码、身份证件和未脱敏资料不得写入仓库或本文档。
5. 标为“待确认”的事项必须由用户决定，执行者不得自行改成“已确认”。
6. 平台套餐、构建限制和免费额度可能变化；部署当天必须重新查看官方文档。
7. 本文命令默认使用 Windows PowerShell，并从本地 `<项目根目录>` 执行。
8. 未获得用户当次明确授权，不执行 git commit 或 git push。

### 1.3 首版完成定义

只有同时满足以下条件，首版才能标记为完成：

- [ ] 指定的公开页面、文章、项目、文档、视频和下载资源均可访问。
- [ ] 本地检查、生产构建和发布检查全部通过。
- [ ] Cloudflare Pages 生产地址通过 HTTPS 访问。
- [ ] 手机与桌面端不存在内容遮挡、横向溢出或无法操作的控件。
- [ ] RSS、Sitemap、404、SEO 元信息和公开下载链接可用。
- [ ] 仓库和构建日志中没有密钥、密码或不应公开的个人信息。
- [ ] 已验证回滚方式，并保留一份可恢复的仓库备份。
- [ ] Stage 5 发布闸门结果为 PASS 或 PASS WITH NOTES。

## 3. 首版范围

### 3.1 P0：首发必须完成

| 模块 | 首版内容 | 最低内容量 |
| --- | --- | --- |
| 首页 | 简介、当前方向、精选文章、精选项目、联系方式入口 | 1 页 |
| 关于 | 个人方向、技术栈、公开联系方式 | 1 页 |
| 博客 | 列表、详情、发布日期、摘要、标签 | 3 篇真实文章 |
| 项目 | 列表、详情、技术栈、贡献、仓库或 Demo 链接 | 2 个真实项目 |
| 文档 | 文档列表、详情或公开下载入口 | 1 份真实文档 |
| 视频 | 项目关联的视频嵌入或外链 | 1 个可播放视频 |
| 下载 | 文件名、类型、大小、版本、更新时间 | 1 个脱敏文件 |
| 基础能力 | 响应式导航、404、RSS、Sitemap、基础 SEO、HTTPS | 全部完成 |

### 3.2 P1：首发有余力再做

- 网页版简历和脱敏 PDF 下载。
- 履历时间线。
- 明暗主题切换。
- 更完整的分类筛选和相关文章。
- 社交分享卡片与定制 Open Graph 图片。

P1 未完成不得阻塞 P0 首发，除非用户在 Stage 0 明确将其中某项升级为 P0。

### 3.3 首版明确不做

- 用户注册、访客登录和会员体系。
- 管理后台、在线编辑器和访客上传。
- 评论、点赞、站内私信和复杂搜索。
- 数据库、FastAPI、Cloudflare Workers 业务接口。
- 自建视频转码、对象存储代理和文件扫描服务。
- Docker、Kubernetes、微服务和首版 Linux 自托管。
- 自动播放背景音乐。后续即使实现，也必须默认关闭并由访客主动开启。

## 4. 技术方案与边界

### 4.1 推荐技术栈

| 类别 | 选择 | 首版理由 |
| --- | --- | --- |
| 前端与构建 | Astro + TypeScript 严格模式 | 静态优先、页面负担低、Markdown 支持成熟 |
| 内容 | Markdown；仅必要页面使用 MDX | 便于版本管理，避免引入后台 |
| 代码仓库 | GitHub | 与部署平台连接，保留完整版本历史 |
| 托管 | Cloudflare Pages 免费方案 | 自动构建、CDN、HTTPS、低运维 |
| 域名 | 首发使用 pages.dev | 不产生域名费用，减少首发阻塞 |
| 视频 | 外部视频平台嵌入或链接 | 避免承担大文件存储和带宽 |
| 大文件 | GitHub Releases 或经确认的公开对象存储 | 避免超过 Pages 和 Git 仓库限制 |
| 数据库与后端 | 无 | 首版不需要动态数据和用户系统 |

### 4.2 请求链路

~~~text
作者 Windows 电脑
    │
    ├── 编辑 Markdown、页面与公开资源
    │
    └── Git push
            │
            ▼
       GitHub Blog 仓库
            │
            └── 触发 Cloudflare Pages 构建
                         │
                         ▼
                   静态 dist 产物
                         │
                         ▼
                  HTTPS + CDN 公开访问
~~~

### 4.3 安全边界

- 公开站点只提供静态 HTML、CSS、JavaScript 和明确允许的下载资源。
- 不存在服务端登录、数据库查询、访客上传和管理接口，因此攻击面显著小于全栈网站，但仍需防范供应链风险、敏感文件泄露、恶意第三方脚本和账号失窃。
- GitHub、Cloudflare 和域名注册商账号必须启用双因素认证。
- MDX 可以执行组件逻辑，只允许维护者本人提交的受信内容使用 MDX；普通文章优先使用 Markdown。
- 仓库一旦提交敏感信息，仅从最新版本删除并不等于从 Git 历史删除。发现泄露时应立即轮换凭据，再处理历史。

### 4.4 资源边界

| 资源 | 位置 | 首版约束 |
| --- | --- | --- |
| Markdown、页面代码 | site/src | 纳入 Git 版本管理 |
| 头像、封面、截图 | site/public | 优先 WebP/AVIF；单图建议不超过 500 KiB |
| 简历和小型 PDF | site/public/downloads | 脱敏；单文件建议不超过 10 MiB |
| ZIP、模型、数据集 | GitHub Releases 或外部存储 | 不直接放入源码目录 |
| 视频 | Bilibili、YouTube 或其他可信平台 | 优先嵌入；不提交原始大视频 |
| 密钥和本地配置 | 本地环境变量 | 不提交；提供无敏感值的示例文件 |

Cloudflare Pages 当前官方页面列出的单个站点资源上限为 25 MiB、每个站点最多 20,000 个文件。平台限制会变化，Stage 4 必须重新核对，不得只依赖本文数值。

## 8. Stage 1：仓库与 Astro 基线

**目标：** 建立可运行、可检查、可构建的最小站点。  
**前置条件：** Stage 0 已通过。

### S1-01 初始化 Git 并配置远端

~~~powershell
Set-Location '<项目根目录>'
git rev-parse --is-inside-work-tree
~~~

如果上一条命令提示当前不是 Git 仓库，再执行：

~~~powershell
git init
git branch -M main
git remote add origin 'https://github.com/Zhou-Jin-Feng/Blog.git'
git remote -v
~~~

如果 origin 已存在但地址不正确，使用以下命令修正：

~~~powershell
git remote set-url origin 'https://github.com/Zhou-Jin-Feng/Blog.git'
git remote -v
~~~

不要把 Markdown 链接语法放进 Git 命令。正确参数是纯 URL。

### S1-02 创建 Astro 项目

~~~powershell
Set-Location '<项目根目录>'
npm create astro@latest site
~~~

安装向导选择：

| 选项 | 选择 |
| --- | --- |
| 模板 | Minimal |
| 安装依赖 | Yes |
| TypeScript | Strict |
| 初始化 Git | No，仓库根目录统一管理 |

随后安装首版需要的官方能力：

~~~powershell
Set-Location '<项目根目录>\site'
npx astro add mdx
npx astro add sitemap
npm install @astrojs/rss
npm install --save-dev @astrojs/check typescript
npm install --save-dev @playwright/test
npx playwright install chromium
~~~

每次集成命令修改配置后都应阅读差异，不要盲目接受与本手册冲突的设置。

### S1-03 建立基础文档和忽略规则

核对 Stage 0 建立的记录文件，并在仓库根目录补齐：

- README.md：项目定位、本地启动、构建和部署入口。
- .gitignore：忽略 node_modules、dist、.astro、本地环境文件、编辑器缓存和系统临时文件。
- .github/workflows/ci.yml：在 push 和 Pull Request 时执行依赖安装、检查、测试和构建。

在 site/package.json 中提供稳定脚本：

| 脚本 | 用途 |
| --- | --- |
| npm run dev | 本地开发 |
| npm run check | Astro 类型与内容检查 |
| npm run test:e2e | Playwright 本地冒烟测试 |
| npm run build | 生产构建 |
| npm run preview | 本地预览生产产物 |

不得忽略 package-lock.json。锁文件必须纳入版本管理，以保证 Cloudflare 构建可复现。

## 10. Stage 3：视觉、媒体、响应式与无障碍

**目标：** 让网站达到可以公开展示的体验标准。  
**前置条件：** Stage 2 已通过。

### S3-01 视觉原则

- 页面以内容阅读和项目检索为主，避免大面积装饰抢占首屏。
- 导航、正文、项目状态、下载操作使用一致的视觉层级。
- 卡片仅用于重复的文章或项目项，不把整个页面章节包装成层层嵌套的卡片。
- 颜色不依赖单一色相表达状态，文本与背景保持足够对比度。
- 字号不随视口宽度无限缩放，长标题和长英文单词不得撑破容器。
- 交互图标优先使用成熟图标库，并为不熟悉的图标提供可见标签或提示。

### S3-02 响应式基线

至少检查以下视口：

| 视口 | 重点 |
| --- | --- |
| 360 × 800 | 导航、长标题、下载按钮、代码块 |
| 768 × 1024 | 列表布局、目录、图片和视频 |
| 1440 × 900 | 正文宽度、留白、卡片密度 |

验收要求：

- [ ] 页面不存在非预期横向滚动。
- [ ] 文本、按钮、标签和代码块不相互遮挡。
- [ ] 导航在触屏和键盘操作下均可使用。
- [ ] 视频和图片具有稳定宽高比，不引发布局跳动。
- [ ] 下载按钮的可点击区域清晰，文件说明不会溢出。

### S3-03 图片、视频和下载

- 图片优先生成 WebP 或 AVIF，并保留准确的替代文本。
- 项目截图展示真实界面，不使用与项目无关的氛围图片。
- 视频默认不自动播放；有声音的媒体必须由访客主动启动。
- 第三方视频使用最小权限和可信域名，不加载无关统计脚本。
- 外链视频不可用时，页面仍显示标题、摘要和直接访问链接。
- 下载文件使用英文、数字和短横线命名，例如 project-report-v1.0.pdf。
- 不提供 EXE、BAT、SCR、私钥、数据库转储或含凭据的配置文件下载。

### S3-04 无障碍与阅读体验

- [ ] 页面有唯一且准确的 H1。
- [ ] 标题层级连续，不为视觉大小跳级。
- [ ] 提供“跳到主要内容”链接。
- [ ] 所有交互元素可通过键盘访问，并有清晰焦点样式。
- [ ] 图片具有有意义的 alt；纯装饰图片使用空 alt。
- [ ] 表单如仅有搜索或联系外链，也必须有可访问名称。
- [ ] 动画尊重 prefers-reduced-motion。
- [ ] 链接文字能够说明目标，不大量使用“点击这里”。

### Stage 3 闸门

三个基准视口全部通过人工检查；键盘可完成全站导航；真实内容没有遮挡、溢出或不可读区域；视频、图片和下载均满足资源规则。

## 11. Stage 4：质量、安全与预发布

### S4-01 执行干净构建

~~~powershell
$sitePath = '<项目根目录>\site'
$nodeModulesPath = Join-Path $sitePath 'node_modules'
Set-Location -LiteralPath $sitePath
if ((Get-Location).Path -ne $sitePath) {
    throw '当前目录不是预期的 site，停止清理。'
}
if (Test-Path -LiteralPath $nodeModulesPath) {
    $resolvedNodeModulesPath = (Resolve-Path -LiteralPath $nodeModulesPath).Path
    if ($resolvedNodeModulesPath -ne $nodeModulesPath) {
        throw 'node_modules 解析结果异常，停止清理。'
    }
    Remove-Item -LiteralPath $resolvedNodeModulesPath -Recurse -Force
}
npm ci
npx astro check
npm run build
~~~

删除前必须确认当前位置是 site，并确认删除目标精确为 site\node_modules。若不能确认，不执行 Remove-Item。不得删除仓库根目录或使用未解析的宽泛路径。

## 14. 常见故障与处理

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 添加 origin 失败 | 非 Git 仓库或 origin 已存在 | 初始化 Git 或更新 origin |
| 仓库返回 404 | 私有仓库、地址错误或未认证 | 核对大小写与 URL，完成 GitHub 登录和权限授权 |
| npm create astro 失败 | Node.js 版本不受支持或网络异常 | 对照 Astro 官方要求更新 LTS，保留完整错误日志后重试 |
| Pages 构建失败 | Node、根目录或锁文件不一致 | 核对 site、锁文件和 Node |
| Pages 部署后 404 | 输出目录错误或路由未生成 | 核对 Build output=dist，并检查 dist 中对应 HTML |
| RSS 或 Sitemap 地址错误 | astro.config 的 site 未设置为生产 URL | 设置生产 site 后重新构建 |
| 视频不显示 | CSP 或平台嵌入策略阻止 | 查看浏览器控制台，仅放行实际使用的可信 frame 域名 |
| 文件无法部署 | 单文件超过 Pages 限制 | 压缩或迁移到 Releases/对象存储，再使用外链 |
| 页面出现横向滚动 | 长链接、代码块、图片或固定宽度组件 | 在 360 px 视口定位元素并设置换行、滚动或响应式约束 |
| 自定义域名证书未生效 | DNS 未传播或记录冲突 | 保留 pages.dev 可访问，检查 DNS，等待后再次验证 |
| 错误版本上线 | 提交或部署选择错误 | 使用 Pages 上一部署回滚，再通过 git revert 修复 |

每次故障记录：发生时间、页面或命令、完整错误、影响范围、处理步骤、最终结果和预防措施。不要只记录“已解决”。

## 15. 后续版本路线

### V1.1：静态体验增强

- 明暗主题切换。
- 客户端全文搜索或小规模静态索引。
- 更完善的标签筛选和相关文章。
- 隐私友好的访问统计。
- 定制 Open Graph 图片。

### V2：作者管理体验

管理面板需求在这里继续评估，不视为取消：

1. 若只需要在网页中编辑 Markdown，优先评估 Git-based CMS 和 GitHub OAuth。
2. 若需要上传大文件、动态修改设置、主题、背景音乐和展示效果，则单独设计受保护的后台。
3. 动态后台必须具备管理员认证、TOTP MFA、恢复码、审计日志、CSRF 防护、限流、上传类型与大小限制、恶意文件扫描和备份恢复。
4. 只有 V2 明确需要长期后端进程时，才重新评估现有 Linux 主机、Docker、反向代理、免费隧道和对象存储。
5. 背景音乐必须默认关闭，提供清晰的播放、暂停和音量控制，并尊重用户偏好。

V2 不得直接在 V1 静态站上临时拼接未受保护的上传接口或管理入口。
